# tumamu — Spec（ハッカソンMVP）

思想は [philosophy.md](./philosophy.md)。前提は、制作期間1〜2日、MR（現実の部屋の壁を使う）、XREAL Aura（Android XR）+ Unity（[技術スタック](#技術スタック)を参照）。

## コア体験ループ

```
触れる → 壁が応答する → つまむ → 壁をもぎ取る → 持つ → 投げる → 浮いて残る
```

| 段階 | ユーザーの動作 | システムの応答 |
|---|---|---|
| 触れる | 指先や手のひらを実際の壁に当てる | 接触点から波紋が広がり、低い音が鳴る。当て続けるほど波紋が深い色に変わっていく |
| つまむ | 壁に触れたまま親指と人差し指を閉じる | その瞬間のカメラ映像から接触点の周りを切り出し、それを貼った塊が指先に現れる |
| もぎ取る | つまんだまま壁から手を離す | 塊が壁から糸を引くように伸びてからちぎれる。壁には剥がれた痕が残る |
| 持つ | つまみ続ける | 材質ごとに「重さ」を表現する（重い材質ほど手の動きに遅れてついてくる） |
| 投げる | 振ってから指を開く | 手の速度を引き継いで飛んでいく |
| 残る | — | 床や壁に当たると材質ごとの音が鳴り、最終的に床から `FLOAT_GAP` だけ浮いて静止する |

### 深さ＝触れている時間
壁に触れ続けた時間で、どの層の材質が出てくるかが決まる。掘るほど地中の深い層に届くという、炭鉱のメタファーになっている。

| 触れている時間 | 層 | 材質 | 見た目 | 投げたときの振る舞い |
|---|---|---|---|---|
| 0〜`LAYER_1_SEC` | 表層 | 現実の壁そのもの | カメラ映像から切り出した壁のテクスチャ | 軽く、よく跳ねる |
| 〜`LAYER_2_SEC` | 中層 | 石炭 | 内側が赤く光る熾火（下の注記を参照） | 重めで、着地時に火の粉が散る |
| それ以上 | 深層 | 大理石 | 白く、うっすら透ける | 重い。着地後に浮遊して静止するまでいちばん長くかかる |

**光学シースルーの制約**：Aura は現実の景色に光を足して表示する方式なので、黒は透明になって見えない。そのため石炭は「黒い塊」ではなく「燃えている石炭」として、発光で表現する。壁から切り出したテクスチャも、暗い部分は透けて見える。デモの壁は明るい色のものを選ぶ。

## 判定パラメータ（初期値。実機で調整する）

| 定数 | 初期値 | 用途 |
|---|---|---|
| `TOUCH_DISTANCE` | 2.0 cm | 指先の関節と壁面の距離がこれ未満なら「触れている」 |
| `TOUCH_GRACE` | 0.3 s | トラッキングが途切れても、この時間は「触れている」状態を保つ |
| `PINCH_DISTANCE` | 1.5 cm | 親指先と人差し指先の距離がこれ未満なら「つまんでいる」 |
| `RELEASE_DISTANCE` | 3.0 cm | つまみの解除しきい値。PINCHより大きくしてヒステリシスを持たせ、チャタリングを防ぐ |
| `THROW_SAMPLE_FRAMES` | 5 | 投げる速度は、指を開く直前の数フレームの平均速度から出す |
| `LAYER_1_SEC` / `LAYER_2_SEC` | 1.0 s / 3.0 s | 層が切り替わる時間 |
| `CROP_SIZE` | 10 cm | 壁から切り出す範囲の、壁上での一辺の長さ |
| `FLOAT_GAP` | 3 cm | 着地後に床から浮かせる高さ（天モクの隙間） |
| `MAX_PIECES` | 20 | 部屋に残す材質の上限。超えたら古いものから消す（性能のため） |
| `MIN_WALL_AREA` | 1.0 m² | これより小さい平面は壁として扱わない |
| `MAX_WALL_DISTANCE` | 2.5 m | 頭から平面までの垂直距離がこれより大きい平面は、壁として扱わない |

### 使う壁の選び方
`ARPlane` は Android XR のランタイムが管理しているので、アプリ側では破棄しない。破棄すると AR Foundation の追跡と食い違うため。その代わり `IWallProvider` で、次の条件をすべて満たす平面だけを壁として扱う。

- 垂直面で、分類が `WallFace`
- `subsumedBy` が null（他の平面に統合されていない）
- 面積が `MIN_WALL_AREA` 以上
- 頭から平面までの垂直距離が `MAX_WALL_DISTANCE` 以下で、頭を平面に投影した点が平面の境界の内側にある

床も同じ考え方で選ぶ（`HorizontalUp`・`Floor`・統合されていないもの）。床は着地と浮遊の基準に使う。平面の可視化はしない（テンプレートの平面表示は外す）。

**実測（2026-11-22、検出モード = 水平 + 垂直）**：40秒で平面が34枚検出され、そのうち17枚は統合済み（`subsumed=True`）だった。床は同じ 55m² の平面が15枚重なっていた。見えていた大量の平面は、ほとんどが統合済みの平面の可視化だった。統合されていない壁は8枚で、面積は 2.1〜11.5m²。0.5〜0.7m² の小さい平面は、すべて Table か Floor だった。頭から平面の中心までの距離は、大きい壁ほど実際より遠く出る（3.2〜7.4m）。そのため、距離の判定には中心ではなく垂直距離を使う。

起動から数秒で、平面が0枚から25〜42枚へ一気に増える。アプリをアンインストールしてから入れ直しても同じだった（42枚、うち壁10枚）。アプリのデータではなく、システムがスキャン済みの部屋の平面をまとめて渡している。遠くの壁や、前にスキャンした場所の平面も含まれるので、上の距離の条件で絞り込む。デモでは、起動した瞬間から目の前の壁が使えるという利点にもなる。

## 技術スタック

**XREAL Aura（Android XR）+ Unity 6 + Kotlin のカメラプラグイン**。

| 役割 | 使うもの |
|---|---|
| XR の基盤 | Unity OpenXR + Android XR パッケージ（`com.unity.xr.androidxr-openxr`） |
| 手 | XR Hands。指先・親指先・手のひらの関節を使う |
| 壁と床 | AR Foundation の `ARPlaneManager`（垂直面のうち wall に分類されたもの） |
| カメラ映像 | `WebCamTexture` で `Camera 0`（前向きの RGB、1920×1080 / 30fps）を使う。Unity の AR Foundation 経由ではカメラ画像を取れないが（[Unity Docs](https://docs.unity3d.com/Packages/com.unity.xr.androidxr-openxr@1.2/manual/features/camera.html)）、`WebCamTexture` なら取れることをフェーズ0で確認した。Kotlin のプラグインは不要 |
| 切り出し | 接触点をカメラ画像の座標に投影し、`CROP_SIZE` に相当する範囲を切り出す。カメラの内部パラメータが取れなければ、頭の姿勢とカメラの画角から近似する |
| 投げる・衝突 | Unity の物理（Rigidbody）。壁と床は、検出した平面から衝突用の形状を作る |
| 浮遊 | 静止を検知したら kinematic に切り替え、`FLOAT_GAP` までゆっくり持ち上げる |
| 演出 | 波紋・火の粉は Shader Graph と VFX Graph（重ければ Particle System） |
| 音 | AudioSource の 3D サウンド |

権限は `android.permission.CAMERA`、手のトラッキングとシーン認識に必要な Android XR の権限、の3つを実行時にリクエストする。

### Jetpack XR（Kotlin のみ）にしなかった理由
カメラの取得は Kotlin の方が素直に書ける。ただ、Jetpack XR の SceneCore には物理エンジンがないし、コードで演出を作るのも Unity よりかなり手間がかかる。1〜2日という期間を考えると、Unity の方が完成に近い。

## 開発環境

普段の開発は Mac の Unity Editor で回す。実機では、Mac に USB でつないで `adb install` でインストールして確かめる。

| 抽象 | 実機の実装 | Editor の実装 |
|---|---|---|
| `IHandInputSource`（指先・親指の位置、つまんでいるか） | XR Hands | XR Interaction Toolkit の XR Device Simulator（マウスとキーボードで手を動かす） |
| `IWallProvider`（壁面の位置と法線） | `ARPlaneManager` | AR Foundation の XR Simulation 環境（部屋のプリセット） |
| `IWallImageSource`（壁の画像） | `WebCamTexture`（`Camera 0`） | Mac の Web カメラ（`WebCamTexture`）か、固定の画像 |

切り替えは起動時に、プラットフォームと権限が許可されているかを見て決める。実機でもカメラの権限を拒否されたら、固定の画像に落とせるようにしておく。

判定ロジック（触れている・つまんでいる・層の切り替え・投げる速度・切り出す範囲の計算）は、Unity に依存しない純粋な C# のクラスにして、Unity Test Framework の EditMode テストで確かめる。

## フェーズ0：実機での検証（2026-11-22 完了）

診断用のスクリプトは `TumamuUnity/Assets/Tumamu/Phase0/`。

- [x] カメラ：`WebCamTexture` で `Camera 0` が 1920×1080 / 27〜30fps で取れる。中身が実際の映像であることも確認した（中心ピクセルの色が頭の動きに合わせて変わる）
- [x] 手：XR Hands で両手の関節が取れる
- [x] 壁：`WallFace` に分類された垂直面を検出できる。ほかに Floor / Ceiling / Table も出る

Aura の公開カメラは ID 0（前向きの RGB）と ID 1（アバター用）の2台だけ。カメラの内部パラメータは取れず、頭に対する位置と向き（外部パラメータ）も取れない。焦点距離 2.4mm とセンサーサイズ 3.2×2.4mm から計算すると、水平の画角は約67°。

**注意（ハマりどころ）**：MR テンプレートの `MR Interaction Setup.prefab` は、平面の検出モードが水平面のみ（`m_DetectionMode: 1`）になっている。値はビットフラグ（1 = 水平、2 = 垂直、4 = 斜め）なので、床と壁を取る `3` に変えた。`-1` にすると斜めの面まで拾ってしまう。

## 技術的な課題

- **壁に触れた瞬間に手のトラッキングが不安定になる。** 手が壁と重なると、カメラから指が見えにくくなる。指先1点で判定せず、手のひらと複数の指の関節を組み合わせて判定する。途切れても `TOUCH_GRACE` の間は「触れている」状態を保つ。
- **壁面の精度。** 検出した平面と現実の壁とでは数cmずれることがある。`TOUCH_DISTANCE` はずれを吸収できる値にする。
- **切り出す位置のずれ。** カメラとディスプレイの位置が違うので、切り出した模様が触れた場所とずれて見える可能性がある。MVP では多少のずれは許容する。
- **投げる動作の安全性。** 現実の部屋で腕を振ることになるので、デモの場所は周りに人や物がない状態にする。

## デモシナリオ（審査用、約3分）

1. グラスを渡し、「壁に触ってみて」とだけ伝える
2. 体験者が触れると壁に波紋が広がり、そこからは自然につまんでもぎ取るまで進むのを待つ。もぎ取ったかけらには、目の前の壁の模様がそのまま付いている
3. 何度か投げると、部屋に壁のかけら・燃える石炭・大理石が浮いた状態で溜まっていく
4. 最後に「深く触れるほど深い層が出る」という仕掛けと、美唄の炭鉱との関係を口頭で説明する

## スコープ外（MVPではやらない）
- 複数人での共有や永続化（部屋に残った材質を次の人が見る、など）
- 壁以外の面（床・家具）からの取り出し
- 材質の加工（彫る・積む）

- [ ] `MIN_WALL_AREA` / `MAX_WALL_DISTANCE` で、目の前の壁だけが残るか
- [ ] 壁に手を当てたときのトラッキングの途切れ方と、`TOUCH_DISTANCE` / `TOUCH_GRACE` の値

- [ ] 実際の手で投げたときの速度の自然さ（`THROW_SAMPLE_FRAMES`）
- [ ] 切り出した模様と、触れた位置のずれ
